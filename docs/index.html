dagRobin

A single source of truth for coordinating multiple AI agents. Tasks are a DAG: each one declares its dependencies, and dagRobin tells you what is ready, what is blocked, and who is already working on it.

Rust + Sled macOS & Linux YAML import/export MIT

Installation

npm — no Rust toolchain needed

npm install -g dagrobin
dagRobin --version

Install downloads the prebuilt binary for your platform from the matching GitHub release and verifies its SHA256 checksum. Supported: macOS and Linux, x86_64 and arm64.

Prebuilt binary

curl -L https://github.com/afa7789/dagRobin/releases/latest/download/dagRobin-macos-arm64.tar.gz | tar xz
sudo mv dagRobin /usr/local/bin/

From source

git clone https://github.com/afa7789/dagRobin.git
cd dagrobin
make install        # cargo install --path .

Updating

# Source / prebuilt installs self-update in place:
dagRobin upgrade             # download, verify SHA256, replace
dagRobin upgrade --check     # exit 0 = up to date, 1 = update available
dagRobin upgrade --force     # replace even if versions match

# npm installs delegate to npm:
npm install -g dagrobin@latest

Quick start

# 1. Initialize in your project root
cd /path/to/your/project
dagRobin init                  # creates .dagrobin/db here
echo '.dagrobin/' >> .gitignore

# 2. Describe the work
dagRobin add setup-db "Create schema"  --priority 1
dagRobin add api      "Build API"      --deps setup-db
dagRobin add ui       "Build UI"       --deps api

# 3. Work it
dagRobin ready                      # setup-db
dagRobin claim setup-db -a alice    # mark it yours BEFORE starting
dagRobin update setup-db --status done

dagRobin ready                      # api is now unblocked
dagRobin status                     # 1/3 (33%)
Always claim first. claim flips the task to in_progress and records the agent. It fails with exit code 1 if someone already holds it — that failure is the lock that stops two agents doing the same work.

Concepts

TermMeaning
TaskA unit of work with an id, title, priority, dependencies, files and free-form metadata.
ReadyStatus pending and every dependency is done. This is what an agent should pick up.
BlockedPending, but at least one dependency is not done yet.
ArchivedStill stored, but hidden from list, ready, blocked and the status round counter.
RoundThe set of non-archived tasks — the batch of work you are running right now.

Statuses: pending → in_progress → done, plus blocked. Priority is a number where lower means more important (1 = must do first, 5 = nice to have).

Database resolution

dagRobin finds its database the way git finds .git/, so subagents running in any subdirectory automatically share one project database.

#SourceNotes
1-d / --db <path>Explicit override.
2$DAGROBIN_DBInherited by subprocesses and subagents automatically.
3.dagrobin/dbWalk-up search from the current directory.
4~/.local/share/dagRobin/dagrobin.dbGlobal fallback.
dagRobin init        # create .dagrobin/db in the current directory
dagRobin which-db    # print the path that would actually be used

Creating tasks

# One-off
dagRobin add t1 "Write documentation"
dagRobin add t2 "Fix critical bug" --priority 1
dagRobin add api "Build API" --deps setup-db --deps auth
dagRobin add ui  "Build UI"  --tags frontend --files src/ui/mod.rs

# Three or more tasks: describe them in YAML and import
dagRobin import tasks.yaml
dagRobin import tasks.yaml --replace   # wipe first, then import

Querying

dagRobin ready                       # tasks whose deps are all done
dagRobin ready --priority-min 2      # only priority 1 and 2
dagRobin blocked                     # what is waiting, and on what
dagRobin list                        # everything active
dagRobin list --status in_progress   # filter by status
dagRobin list --tags frontend        # filter by tag
dagRobin list --include-archived     # archived tasks too
dagRobin get api                     # full detail for one task
dagRobin check api                   # exit 0 if ready, 1 if not

Every listing takes --format table|json|yaml. check prints nothing and is meant for shell scripts:

if dagRobin check api; then dagRobin claim api -a worker-1; fi

Claiming & updating

dagRobin claim api -a worker-1           # exit 1 if already claimed
dagRobin update api --status done
dagRobin update api --title "New title"
dagRobin update api --description "..."

# Metadata: semicolon separates pairs, commas are allowed inside values
dagRobin update api --metadata "notes:took 2h, tricky;reviewer:bob"
dagRobin update api --metadata "notes:test" --metadata "agent:me"

dagRobin delete api            # refuses if other tasks depend on it
dagRobin delete api --force    # delete anyway

Progress, archive & clear

Over a long-lived project the database accumulates hundreds of finished tasks, and 10/1230 tells you nothing about the feature you are shipping today. archive parks old work so the counter reflects the current round only.

dagRobin status          # alias: dagRobin progress
Round:     10/120 (8%)
  pending 108  in_progress 2  blocked 0
Archived:  380/380
All-time:  390/500 (78%)
# Before a big round: park what is finished
dagRobin archive                              # default: every done task
dagRobin archive t1 t2                        # specific ids
dagRobin archive --status done --status blocked
dagRobin archive --tags sprint-3
dagRobin archive --all                        # everything still active
dagRobin archive --undo --all                 # bring it all back

# Permanent deletion — there is no undo
dagRobin clear --yes
dagRobin clear --yes --status done
dagRobin clear --yes --archived-only
archive vs clear. archive keeps history — archived tasks still count under All-time and can be restored with --undo. clear deletes rows permanently and requires --yes.

File conflicts

The files: field on a task declares what it will touch. Before dispatching agents in parallel, ask dagRobin which tasks collide.

dagRobin conflicts                         # all non-done tasks
dagRobin conflicts --ready-only            # only tasks ready right now
dagRobin conflicts --status pending
dagRobin conflicts --format json           # for automation
Conflict: src/main.rs
  - implement-auth: "JWT middleware" (Pending)
  - fix-main-routing: "Fix router" (Pending)

Resolution: either make one task depend on the other, or hand both to the same agent.

Graph & export

dagRobin graph                             # ASCII tree
dagRobin graph --format mermaid            # paste into Markdown
dagRobin graph --format dot --output dag.dot
dagRobin export tasks.yaml                 # snapshot everything
dagRobin export done.yaml --status done    # filtered snapshot

YAML schema

This is what import reads and export writes. Only id and title are required.

- id: implement-auth
  title: JWT auth middleware
  description: Short summary shown in listings
  status: Pending            # Pending | InProgress | Done | Blocked
  priority: 1                # lower = more important
  deps: [setup-db]
  files: [src/auth/mod.rs]   # used by `conflicts`
  tags: [backend]
  archived: false
  metadata:
    long-description: |
      Axum middleware that extracts the Bearer token from the Authorization
      header, decodes it with HS256 and JWT_SECRET from Config, and injects
      Claims { sub, exp, role } into the request extensions.
      On a missing or invalid token: 401 with JSON { "error": "Unauthorized" }.
Write a real long-description. Builder subagents have no access to the original conversation. That metadata field is their only source of truth — a task without it gets implemented by guessing.

AI agent integration

Drop this into your CLAUDE.md (or the equivalent for your tool) so every agent follows the same protocol.

The complete protocol — worker and orchestrator blocks, race-safe claiming, and the mistakes agents actually make — is in AGENTS.md. The short version:

## Task coordination — dagRobin

Before starting ANY work:
1. `dagRobin ready` — see what is available
2. `dagRobin claim <id> -a <your-name>` — claim it. Exit code 1 means
   another agent already has it: pick a different task.
3. Read `metadata.long-description` — that is the spec.
4. Do the work.
5. `dagRobin update <id> --status done`

Rules:
- The orchestrator creates and assigns tasks but NEVER claims them.
- Workers claim before starting, always.
- Check `dagRobin conflicts --ready-only` before dispatching parallel agents.

Runnable examples

Three task files in the repo, each demonstrating one pattern. They import cleanly into a fresh database.

FilePattern
01-web-app.yamlA dependency chain — a feature built front to back, in order.
02-parallel-round.yamlMaximum parallelism — five independent tasks converging on one integration task.
03-bugfix-round.yamlTriage — no dependencies; priority does the ordering.

Try one against a scratch database, so nothing real is touched:

export DAGROBIN_DB=/tmp/dagrobin-demo
rm -rf "$DAGROBIN_DB"

dagRobin import examples/01-web-app.yaml
dagRobin ready                    # setup-db — the only thing not blocked
dagRobin status                   # Round: 0/5 (0%)

dagRobin claim setup-db -a demo
dagRobin get setup-db             # read metadata.long-description — the spec
dagRobin update setup-db --status done

dagRobin ready                    # auth-middleware unlocked
dagRobin status                   # Round: 1/5 (20%)

Prove what conflicts is for by deliberately breaking the parallel round:

dagRobin import examples/02-parallel-round.yaml
dagRobin conflicts --ready-only
# No file conflicts detected.

dagRobin add rogue "Also edits the header" --files src/components/Header.tsx
dagRobin conflicts --ready-only
# Conflict: src/components/Header.tsx
#   - rogue: "Also edits the header" (Pending)
#   - ui-header: "Site header component" (Pending)

Running big rounds

  1. dagRobin archive — park the previous round so the counter starts clean.
  2. dagRobin import round-5.yaml — load the new batch (keep it to 15–20 tasks, 30–60 min each).
  3. dagRobin conflicts --ready-only — find file collisions and serialize them with dependencies.
  4. Dispatch agents; each one claims, works, marks done.
  5. dagRobin status — watch the round fill up.
  6. dagRobin export .claude/tasks-snapshot.yaml — snapshot before the next round.
